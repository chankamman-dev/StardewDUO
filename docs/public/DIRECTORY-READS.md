# 按需目录读取与缓存

图鉴、收集包与剧情事件只在相关页面需要时读取。离开页面、隐藏或暂停下屏后，请求停止，游戏端的读取租约自然过期。新存档会清空下屏缓存，语言或内容变化会使游戏端目录失效。

图鉴的四种原版分类共用一次分帧物品目录扫描。后续刷新复用分类和名称，重新读取实际收集、捐赠、出货和烹饪进度；没有变化时保留已序列化的报告。第三方图鉴仍受已支持版本和数量限制约束。

事件和收集包每次游戏更新可处理的条目数分别提高至 32 和 16，仍保留原有 1.5 毫秒软预算、容量上限及游戏线程限制。单条原生读取无法被中途抢占，因此这不是硬实时保证。冷却期间不占用这三类采集器的调度轮次。

下屏分页最多同时读取四页，只有版本、语言、来源数量和目录类型一致的完整结果才会替换页面数据。临时中断会保留已验证的分页；返回页面时核对首页版本，只下载缺少的页。版本变化会重新读取，避免混合不同目录。缓存仅在当前 App 会话内有效。

冷启动相关页面时，优先生成该页面的主报告；主报告就绪后再请求需要的物品或居民目录，避免大型目录和图片导出抢占首轮采集。事件仍是完整结果后显示，不以部分页冒充完整查询。

电脑隔离游戏与契约测试用于检查完整性、缓存复用和只读边界。大量模组下的 Thor 加载时间与持续帧率需要另行实机验收，不能由电脑测试推断。
