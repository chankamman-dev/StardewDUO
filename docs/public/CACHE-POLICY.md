# 缓存、采集与加载时间

双屏模组会复用已经读取的静态资料，但不会把背包数量、任务完成状态和居民实时位置当作永久资料缓存。缓存命中后仍读取当前游戏状态；领奖、制作等操作执行前重新核对原生数据。

## 当前机制

- 日历复用原生生日和节日目录，按当前已知信息、日期与条件生成显示结果。
- 原生制作配方复用已解析的模板，最多 256 条。配方文本、职业、语言、存档或内容变化会失效；带动态标记或构造方法被其他模组修改时绕过复用。材料数量和可制作次数每次重新读取。
- 核心资料分阶段读取，完整一轮完成后才替换上次结果。首次完成约需一秒，后续短暂保留上次完整结果；操作前强制读取当前资料。
- 农务扫描只在 `/v1/farm` 的读取需求有效时进行。普通快照、居民或地图页不会顺带启动它；离开农务页后租约过期，扫描停止。
- 头像或事件资产失效只刷新相应资料，保留无关目录缓存。无法确定依赖的资产仍采用完整失效，优先保证内容正确。
- 图鉴、收集包、剧情事件继续使用分帧读取、按需租约、完整版本分页与已序列化结果复用，详见 [目录读取](DIRECTORY-READS.md)。

这些主要是**本次游戏会话内的缓存**。没有将游戏或 Content Patcher 的全部最终资产持久化到磁盘，也没有实现跨启动的着色器缓存。模组资产可依赖存档、日期、天气、配置和模组版本；复用错误的最终资产会造成旧头像、错误地图或任务状态。未来的磁盘缓存必须有完整依赖标识、失效和回退机制。

## 加载与帧率的区别

减少重复采集可以减轻游玩中的帧开销，但不保证缩短游戏启动或读档。大量模组的初始化、地图解析和存档重建仍由游戏及第三方模组处理。电脑隔离环境的桥接开关对照用于定位瓶颈，不能代表 Thor 上的加载速度或持续帧率。

性能计时只保留固定大小的环形窗口；不在游戏线程遍历堆内存。命名段的耗时有助于定位长帧，但单次原生调用不能被中途抢占，分帧预算属于软预算。
