# 模组居民头像

App 0.11.1-dev.12 / 游戏模组 0.10.1-dev.12。

居民列表、档案、生日日历、任务中的居民与情境卡片共用头像来源。普通立绘来自当前 NPC；没有生成游戏对象的居民可以读取其资料指定的默认立绘素材，不会为读取头像创建居民。

支持 Portraiture **1.12.1-alpha.20240304** 的已加载图片包：读取当前图片包、居民预设、地点和季节选择，展开 ScaledTexture2D 的真正纹理，将首个表情完整缩成 64×64。动画使用稳定的首帧。不会调用会修改全局选择的 getPortrait，不改变图片包设置或动画状态。其他版本和 HDP 动态来源尚未验证；无法识别时保留原生图片或明确的占位图。

游戏端共享处理结果，居民目录、地图档案和情境读取同一张图片不再重复读取 GPU。按实际纹理与表情区域缓存，单帧上限 512×512、最多 2048 个缓存条目；新存档清理来源和最后有效图片。无关素材失效不清理这份头像缓存。同一存档刷新时保留最后有效的图片地址。

纯白、纯色或完全透明的占位图不作为有效头像发布。下屏也会检测旧版本传来的空图，依次尝试目录立绘、地图头像或原版/居民占位图。图片不存在时有有限的兜底链，不无限重试。验证结果最多缓存 512 项，相同来源重复刷新不重复验图。

目录中的头像只是显示资料；防剧透规则仍决定哪些居民可见。没有适配图片的角色不会凭空生成立绘。

自动检查覆盖选择优先级、预设不改变全局图片包、动画不推进、完整高清表情缩小、占位图拒绝，以及浏览器中居民和生日日历的加载失败兜底。电脑回归不等于 Thor 实际运行验收。
# 情境页兼容性

居民情境卡的头像可以是游戏端已缓存的 `/bridge/asset/` 加64位小写十六进制摘要链接，或旧版内嵌PNG。下屏按与其他居民头像相同的本地资源规则校验，不接受远程地址、文件路径或任意图片协议。头像校验失败不能被解释为物理连接断开：收到回应但数据格式不匹配时，页面提示游戏数据暂时无法读取；HTTP失败和实际中断仍提示连接异常。
